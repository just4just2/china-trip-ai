# china-trip-ai

Голосовой переводчик RU⇄ZH и ассистент с веб-поиском для поездки в Китай. PWA из двух файлов, без сборки и зависимостей.

- `index.html` — всё приложение (UI + JS). `sw.js` — кэш страницы, чтобы она открывалась, когда github.io в Китае недоступен.
- API: OpenAI-совместимый `chat/completions` со стримингом. По умолчанию OpenRouter; ключ живёт в localStorage телефона.

## Не ломать
- Из Китая OpenRouter отдаёт 403 на модели OpenAI/Google/Anthropic → по умолчанию только китайские (Qwen, MiMo, DeepSeek).
- Голос: MediaRecorder → WAV 16 кГц → `input_audio` в omni-модель. Не переходить на Web Speech API: на Android он ходит в Google, в Китае не работает.
- Никаких внешних CDN и шрифтов — в Китае не грузятся.
- Ответы модели выводить только через `textContent`, не `innerHTML`: инъекция из веб-поиска утащит ключ.
- После записи останавливать трек микрофона, иначе iOS играет озвучку в тихий разговорный динамик.
- Ссылки карт ведут только на зашитые хосты Apple Maps и Amap; модель задаёт только текст запроса.
- Память ассистента не передаётся переводчику.

## Проверка
- Самотест: открыть `index.html#test` → «✅ selftest ok».
- Полный прогон без ключа: `node dev/mock.mjs` (или preview `translator-mock`), в ⚙ URL `http://localhost:8765/openrouter.ai/v1/chat/completions`, любой ключ. Запросы печатаются в stdout.
- Реальный API проверяется только с ключом на телефоне.

## Деплой
GitHub Pages из корня ветки `main`.

### Обновление PWA и кэша — обязательно при каждом релизе приложения
- При изменении `index.html` или `sw.js` увеличивать видимую версию в ⚙ (`Версия YYYY.MM.DD.N`) и менять имя `CACHE` в `sw.js` на новое `china-trip-ai-vN`. Публиковать оба файла одним коммитом: изменение worker запускает установку свежего кэша. Для изменений только документации версии не трогать.
- Сохранять регистрацию worker с `updateViaCache: 'none'`. В `install` сначала успешно загрузить страницу через `Request('./', {cache: 'reload'})`, затем вызвать `skipWaiting()`. В `activate` — `clients.claim()`. Не активировать новую версию до успешного заполнения кэша.
- Обычное открытие остаётся stale-while-revalidate ради работы без сети в Китае. Фоновую загрузку и запись ответа в кэш обязательно удерживать через `event.waitUntil(...)`, даже если сохранённая страница уже показана.
- Кнопка «Обновить приложение» запрашивает страницу с `cache: 'reload'`. Worker обязан для такого запроса вернуть сетевой ответ и дождаться его записи в кэш; только затем страница перезагружается. При ошибке или таймауте сохранить офлайн-копию, показать ошибку и разрешить повтор.
- Не считать `?v=...` гарантированным обходом кэша: `cache.match(..., {ignoreSearch: true})` игнорирует query. Новый worker также не заменяет HTML уже открытой вкладки: нужно обновление страницы или повторное открытие приложения.
- Не предлагать очищать данные сайта или localStorage ради обновления: там API-ключ, лента, закладки и память. Не удалять все Cache Storage на github.io — другие проекты того же origin могут использовать свои кэши.

### Проверка публикации
1. До push проверить переход именно со старым установленным worker и старой страницей в кэше: новая версия устанавливается, после перезагрузки виден новый номер, лента/закладки/память сохранены.
2. Проверить кнопку обновления поверх устаревшего кэша. Без сети сохранённая страница должна открываться, а неудачное обновление не должно уничтожать кэш или данные.
3. После push дождаться GitHub Pages и проверить публичные `index.html` и `sw.js`: они должны соответствовать опубликованному коммиту. Одного успешного push или HTTP 200 недостаточно. Открыть публичный `index.html#test` → «✅ selftest ok».
4. Сообщить пользователю ожидаемый номер версии в ⚙ и дать ссылку на `https://just4just2.github.io/china-trip-ai/index.html`. Если телефон всё ещё показывает старую копию, открыть сайт с интернетом, дождаться обновления worker, затем перезагрузить/переоткрыть PWA. В новой версии использовать ⚙ → «Обновить приложение» и сверить номер.
